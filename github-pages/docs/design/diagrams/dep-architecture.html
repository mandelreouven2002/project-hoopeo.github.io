DEP Server Architecture

How a statement travels from an untrusted client through the trusted DEP server, using the clinic's six consumers

Trust boundary

  • • Clients hold only a SQL connection over the PostgreSQL protocol
  • • Keys, data, and enforcement live in the server process
  • • The path is fixed at authentication; no statement can change it
  • • An embedded build of the same rules would protect nothing

Enforcement in the pipeline

  • • The analyzer checks resolved meaning, not SQL spelling
  • • Anchoring, typing, and path rules are decided before any row is read
  • • The final plan is re-checked after optimization
  • • Matching compares keyed index entries, never plaintext

What leaves the server

  • • Ordinary values, as ordinary permissions allow
  • • Protected values only as SQL NULL
  • • Disclosed values only from declared DISCLOSES functions
  • • Errors that name rules and objects, never values
