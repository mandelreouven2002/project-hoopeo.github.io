Database-enforced
privacy.

Use sensitive values without exposing them in ordinary query results. Database-Enforced Privacy (DEP) separates permission to find records, link datasets and release protected values.

Declare the rules in the schema. The database applies them to every connected client.

How DEP works

The right to use a value
doesn't have to mean
the right to read it.

Different applications need different operations: look up a record, compute statistics, or release an identifier for an approved task. Express those decisions in the database schema and permissions.

A worked example

One dataset. Four operations.

To make the rules concrete, this example uses a small clinic. Compare finding a record, reading identifiers and joining protected records with and without an anchor.

Protection starts in the schema.

Here, the national ID is the protected value. A shared match domain lets related protected columns match each other.

CREATE TABLE patients (
  patient_id  BIGINT PRIMARY KEY,
  national_id TEXT PROTECTED MATCH DOMAIN person_id,
  full_name   TEXT
);

Finding a record does not require returning its identifier. Linking the entire dataset is a separate operation.

Know the boundary

Designed to demonstrate a model.

DEP Engine is experimental software for evaluation. PostgreSQL wire compatibility is not full PostgreSQL compatibility. Protected identifiers do not make other fields anonymous, and DEP does not establish GDPR compliance.
