Database-Enforced Privacy (DEP)

SQL that uses personal data without handing it out

DEP SQL is SQL with the privacy rules in the schema. Mark a column PROTECTED, and applications can still find, check and connect records with it, but no query gets the value back. The few exceptions are named functions, granted and audited. DEP Engine, the database server, enforces it for every client.

The same lookup, three outcomes

Find a patient by ID number, without being handed the ID numbers

Reception types the ID number a patient presents. A regular database answers with the row, ID number included, and the same privilege lets the next query read every ID number in the table. DEP finds the row by comparing a keyed fingerprint of the number (its blind index entry), and returns the column as NULL. A query that would connect every patient to every diagnosis is refused before it reads a row.
